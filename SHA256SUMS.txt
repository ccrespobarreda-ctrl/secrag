# Integrity of the frozen release SECRAG-RRF40-2026-08-17.
#
# TWO KINDS OF ENTRY, AND WHY ONE OF THEM CANNOT BE CHECKED
#
# This file used to make one claim about sixteen files and could not keep it.
# Nine of them are evidence -- the results behind every published figure, the
# configuration they were measured under, and the manifests. Those verify, and
# are verified on every push.
#
# Five are the retriever and the three harness modules. They were hashed at
# 17:42 on 17 August, from a working tree, and edited before anything was
# committed. Three searches establish it, and all three are in the repository
# so the claim can be re-tested instead of believed:
#
#   verify_release.py        the bytes match neither the working tree nor the
#                            release tag
#   find_release_commit.py   no commit of the 42 in this repository holds them
#   find_release_blobs.py    none of the 195 blobs in the object database holds
#                            them, reachable or orphaned
#
# So those five can never pass. They are marked `record`: the published value
# stays visible and nothing pretends to check it. A check that can never pass
# is not a check, it is a red build waiting to be switched off, and this
# repository documents what happens to a check nobody runs.
#
# What remains true is in FINAL_RELEASE_MANIFEST_ADDENDUM.md: those figures
# were produced by this code, the results files are byte-identical to
# publication, and finding 6 reproduced all twelve retrieval figures a week
# later from a modified harness. What is not true, and was implied by listing
# these five as release artifacts, is that a reader can check out the release
# and reproduce the bytes.
#
# WHICH BYTES THESE HASH
#
# Computed on Windows, over CRLF. .gitattributes stores text with LF and checks
# it out however the platform wants, so a clone elsewhere holds the same content
# in different bytes and a plain `sha256sum -c` mismatches every entry -- which
# is why this list went unchecked for weeks while one of its entries was false.
# verify_release.py recovers the hashed form instead of the hashes being
# rewritten: FINAL_RELEASE_MANIFEST.md carries twelve of these in the same form
# and is itself frozen.
#
# WHAT IS NOT LISTED
#
# Living documents. README.md and docs/handoff-final-es.md were listed here and
# have been removed: the README's hash had been false since 30 August, when the
# demo commit changed the file. A frozen artifact list cannot hold a document
# that is expected to change, and the freeze rule never claimed it did.

# measured under. If one of these changes, something is wrong, and the answer
# is not a new hash.
